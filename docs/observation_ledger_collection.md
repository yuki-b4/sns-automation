# 観測台帳 収集レシピ（30件を5時間で）

対象: 事業ロードマップ スプレッドシート（`1eb-P739JJs7qi1c9Uzy_WpZhy0gsCag382YzohFOBEY`）の
`法人_90日WBS_アクション` シート「準備｜観測台帳を作る（求人を出し続けている事業所を100件）」。

最初の30件を、1週間ではなく **5時間** で埋めきるための手順書。
配点の記述はスプレッドシートの説明文ではなく **`観測台帳` シートに実装されている数式そのもの** から起こしている。

## 1. 配点の実体（数式から確定）

`観測台帳` の 4〜123 行（No.1〜120）に入っている数式:

| 列 | 内容 | 種別 |
|---|---|---|
| A | No. | 既存の連番（触らない） |
| B〜I | 事業所名／業種／エリア／責任者の呼び名／推定人数／単一拠点／中間管理職／時給・シフト中心 | **入力** |
| J | 境界判定 | **数式** |
| K〜L | トリガー／掲載開始日 | **入力** |
| M | 継続週数 | **数式** |
| N〜O | 観測メモ／出所 | **入力** |
| P | スコア | **数式** |
| Q | ランク | **数式** |
| R〜S | 予定チャネル／ステータス | **入力** |
| T〜V | 接触回数／最終接触日／直近の反応 | **数式**（`接触ログ` 連動） |
| W〜Y | 次アクション／期限／備考 | **入力**（接触後に手で埋める） |

```
J4 =IF($B4="","",IF(OR($G4="いいえ",$H4="あり"),"対象外",
      IF(OR($F4="",$G4="",$H4=""),"要確認",
      IF(AND($F4>=5,$F4<=30),"適合","対象外"))))

M4 =IF($L4="","",ROUNDDOWN((TODAY()-$L4)/7,0))

P4 =IF($B4="","",IF($J4="対象外",0,
      IFERROR(VLOOKUP($C4,'マスタ_選択肢と配点'!$A$4:$B$14,2,FALSE),5)
    + IFERROR(VLOOKUP($K4,'マスタ_選択肢と配点'!$D$4:$E$8,2,FALSE),0)
    + IF($M4="",0,IF($M4>=8,20,IF($M4>=4,10,0)))
    + IF($J4="適合",20,10)
    + IF($I4="はい",5,0)))

Q4 =IF($B4="","",IF($J4="対象外","除外",IF($P4>=70,"A",IF($P4>=50,"B","C"))))
```

### ここから読み取れる、調べ方に効く5つの事実

1. **満点は 100 点ではなく 105 点**（業種30＋トリガー30＋継続20＋境界20＋時給5）。
   マスタの「満点100点」は説明文だけで、数式に上限のクリップは入っていない。
   A判定の 70 点は実質 105 点満点に対する 67%。思っているより A は取りやすい。

2. **A判定の主導権は業種ではなく「トリガー×継続週数」が握っている。**
   - 境界適合(20)＋時給はい(5)＝25 は、対象になる店ならほぼ自動で付く
   - そこに トリガー「求人を出し続けている」(30) ＋ 継続8週以上(20) が乗ると **75点 → 業種が「その他」5点でもA**
   - 逆に 業種がカフェ(30) でも トリガーなし・継続不明だと 30+20+5=55 で **B止まり**

   → **業種で探すのではなく、掲載が古い求人から探す。** これが工夫の核心。

3. **業種名・トリガー名がマスタと1文字でも違うと、黙って減点される。**
   `VLOOKUP(...,FALSE)` が外れると `IFERROR` で業種は **5点**、トリガーは **0点** に落ちる。
   エラー表示は出ない。「カフェ」と書くと（正しくは「珈琲屋・カフェ」）**25点＝ランク1つ分**が消える。
   最大の事故源。必ずマスタからコピーして貼る。`tools/observation_ledger_score.py` で事前検算する。

4. **`単一拠点` `中間管理職` に「不明」と書くと、確認していないのに「適合」＋20点が付く。**
   `J` は `""`（空欄）だけを「要確認」に落とす実装なので、「不明」は空欄扱いされず、
   推定人数が5〜30ならそのまま「適合」になる。
   → **確認できていない項目は「不明」ではなく空欄のままにする**（→「要確認」＋10点）。
   差は10点しかない。ここを水増しすると「A×未接触」の棚が信用できなくなり、
   週10件の声かけ先の選定そのものが壊れる。10点のために壊す価値はない。
   （`責任者の呼び名` の「不明」は点数に無関係なので、こちらは遠慮なく使ってよい）

5. **`掲載開始日`(L) は必ず日付として入れる。** 文字列だと `M` が計算できず、20点を取り逃す。
   `2026/06/10` 形式で入力し、セルが右寄せになっていることを確認する。

## 2. 1枚の求人票から取れるもの（＝順序を間違えない）

求人票 **1枚** で、最大 55点分と境界判定20点の材料が同時に確定する。

| 求人票で分かること | 埋まる列 | 効く点 |
|---|---|---|
| 受付年月日 / 掲載開始日 | L →（Mが自動計算） | +20（8週以上）／+10（4週以上） |
| その求人が長期間出ている | K =「求人を出し続けている」 | +30 |
| 賃金形態が時給 | I =「はい」 | +5 |
| 従業員数 | F | 境界判定の材料 |
| 就業場所が1か所 | G | 同上 |
| 仕事内容の具体的な一文 | N（観測メモ） | 点数外だが手紙の一文目になる |

Googleマップは **裏取り専用**（単一拠点の確認・規模感・責任者の呼び名・観測メモの補強）。
マップから入って求人を探すと1件あたりの時間が倍になる。**必ず求人媒体から入る。**

## 3. 媒体の選び方

継続週数(+20)とトリガー「出し続けている」(+30)＝**合計50点は、掲載開始日が分かる媒体でしか確定できない**。
媒体の優劣はここだけで決まる。

| 媒体 | 掲載開始日 | 従業員数 | 単一拠点 | 時給 | 高得点業種の当たり |
|---|---|---|---|---|---|
| **ハローワークインターネットサービス** | ◎ 受付年月日が明記 | ◎ 企業全体／就業場所を別記 | ◎ 就業場所で判定できる | ◎ 賃金形態 | △ カフェ・美容室は少なめ |
| Indeed | △ 「30日以上前に掲載」表示止まり | × | × | ○ | ◎ |
| 求人ボックス | ○ 掲載日が出れば使える | × | × | ○ | ◎ |
| タウンワーク | △ 掲載期間が週更新 | × | × | ◎ | ◎（アルバイト） |
| 店頭の貼り紙 | × | × | ◎ 現物で分かる | ○ | ◎ |
| Googleマップ | × | × | ◎ | × | ◎ |

**ハローワークが「継続週数＋境界判定」を一撃で確定できる唯一の媒体。** 5時間30件のエンジンはここ。
足りない業種点（カフェ・美容室・小規模宿）は Indeed／求人ボックス／タウンワークで補う。

### ハローワーク側の手順

1. 求人情報検索 →「詳細検索」（フリーワード検索は使わない）
2. 就業場所: `{都道府県}` + `{市区町村}`
3. 雇用形態: **パート**（時給・シフト中心＋5 をここで確定させる）
4. 産業分類（大分類）を1つずつ回す:
   - 宿泊業，飲食サービス業 …… 珈琲屋・カフェ / 小規模宿・ゲストハウス / 飲食（カフェ以外）
   - 生活関連サービス業，娯楽業 …… 美容室・サロン / フィットネス・小規模ジム
   - 教育，学習支援業 …… 学習塾
   - 医療，福祉 …… 整骨院 / 歯科医院 / クリニック / 小規模介護・保育
5. 並び替えに「求人受付年月日」があればそれを選ぶ。昇順が選べなければ結果一覧に受付年月日が出るので、
   **古いものから拾う**（新着は継続週数が稼げないので後回し）。
6. 求人票で見るのは次の5点だけ。それ以外は読まない:
   - 事業所名 / 就業場所（市区町村）
   - 受付年月日 → L
   - 従業員数（就業場所） → F。企業全体と同数なら G=はい
   - 賃金形態が時給 → I=はい
   - 仕事内容の1〜2文 → N の材料
7. **従業員数が 5〜30名の範囲外なら3秒で閉じる。** これがスピードの肝。

ハローワーク求人の有効期間は受付日の翌々月末までなので、
**受付年月日が今日から8週以上前＝いま現在も出続けている** ことがそのまま確定する。
ここが「継続週数」を推測でなく事実として書ける理由。

### Indeed / 求人ボックス / タウンワーク側（業種点を取りに行く）

`{エリア}` を市区町村名か最寄駅名に置き換えて使う:

```
{エリア} カフェ アルバイト
{エリア} 珈琲 焙煎 スタッフ 募集
{エリア} 美容室 アシスタント 求人
{エリア} 美容師 スタイリスト 募集 個人サロン
{エリア} ゲストハウス スタッフ 募集
{エリア} 旅館 小規模 フロント パート
{エリア} 個人経営 飲食 ホール キッチン
{エリア} 学習塾 講師 パート
{エリア} パーソナルジム トレーナー 募集
```

- 絞り込み: 雇用形態＝アルバイト・パート
- Indeed の投稿日フィルタは新しい側しか絞れないので、**新着を除外する側**に使い、
  一覧に「30日以上前に掲載」の表示があるものを拾う（＝4週以上 → +10 が確実に取れる）
- 掲載日が出る媒体ならその日付を L に入れる
- 掲載開始日がどうしても分からないときの代替: 求人票に「急募」「アットホーム」の文言があれば
  K =「急募・アットホームの文言」で **+20**（継続30には届かないが0ではない）

**8週の確定に2分以上かけない。** 4週で +10 を確定させて次に行くほうが、
1件を完璧にするより30件そろえる価値が高い。

### Googleマップ（裏取り・1件60〜90秒）

1. 店名で検索 → **他店舗があればチェーン。G=いいえ → 対象外。即捨てて次を補充**
2. 口コミ数・写真の枚数・席数から規模感 → F の裏取り
3. 口コミ返信を誰が書いているか → E（店長／オーナー店長／オーナー／院長／施設長 …）
4. 直近の口コミ1件 → N（観測メモ）の材料

## 5. 観測メモ（N列）の書き方

点数には効かない。効かないが、手紙の一文目と訪問の名乗りがここから出るので、ここだけは手を抜かない。

- **媒体名を書かない。** 「Indeedで見ました」は接触反応 A（営業の棚）に直行する
- 「〇週間求人を出し続けていますね」も同じ理由で使わない。観測は手札であって挨拶ではない
- **相手が自分で書いた言葉を引く**のが最も効く

良い例:
- 「求人票の『一緒に長く働ける方を』という一文」
- 「口コミの返信をオーナーご自身が書かれている（署名が店主名）」
- 「6月から週末の営業時間を1時間短縮している」
- 「求人の仕事内容に『新人研修は先輩が付きっきり』と書かれている」

避ける例:
- 「求人を8週間出している」（＝観測の生データ。一文目にすると監視に聞こえる）
- 「人手不足のようですね」（＝決めつけ）

## 6. 貼り付け手順（数式を壊さない）

`J` `M` `P` `Q` `T` `U` `V` は数式。**`B4:Y33` を一括で貼ると数式が消え、以降スコアが二度と出ない。**
必ず4ブロックに分けて、**値のみ貼り付け（Ctrl+Shift+V）** で貼る。

| # | 貼り付け先 | 収集シートの列 | 内容 |
|---|---|---|---|
| 1 | `B4:I33` | 1〜8列目 | 事業所名／業種／エリア／責任者の呼び名／推定人数／単一拠点／中間管理職／時給・シフト中心 |
| 2 | `K4:L33` | 9〜10列目 | トリガー／掲載開始日 |
| 3 | `N4:O33` | 11〜12列目 | 観測メモ／出所 |
| 4 | `R4:S33` | 13〜14列目 | 予定チャネル／ステータス |

- A列（No.）は既存の連番。触らない
- W／X／Y（次アクション・期限・備考）は接触後に手で埋める
- 貼った直後に `Q4:Q33`（ランク）に A/B/C が出ているか目視する。空欄なら B列が空、`除外` なら境界が対象外

**もし J/M/P/Q を消してしまったら**: §1 の数式を4行目に貼り直し、`J4:Q4` をコピーして `J5:Q33` に貼る。
相対参照なのでそのまま効く。

## 7. 貼る前の検算

```bash
python3 tools/observation_ledger_score.py tools/observation_ledger_template.tsv
```

`観測台帳` と同じロジックで 境界判定／継続週数／スコア／ランク を再現し、
シート側では黙って減点されるだけの次の事故を落とす:

- 業種名がマスタ11種と不一致（→ 5点に落ちる。最大25点の損）
- トリガー名がマスタ5種と不一致（→ 0点に落ちる。最大30点の損）
- `単一拠点` `中間管理職` に「不明」（→ 未確認なのに適合＋20が付く水増し）
- 掲載開始日が日付として読めない（→ 継続週数が計算されず最大20点の取り逃し）
- 推定人数が数値でない

`--today YYYY-MM-DD` で基準日を変えられる（シートの `TODAY()` に相当）。

## 8. 選択肢の正本（マスタ_選択肢と配点）
