# ピン留め投稿案

最終更新: 2026-08-13

> Threads プロフィールにピン留めする投稿の案。**本ファイルは実行時に読まれない**（プロンプト生成に利用されない）参照ドキュメントで、運用者が案を選んで手動でピン留めする。
>
> 本文執筆ルールの正本は `scripts/generate_post.py:build_prompt` の「共通ルール」／型カタログ。プロフィール文・アカウント名は `docs/social_profiles.md`、ポジショニング・ペルソナは `config/strategy.json` を参照。

---

## 1. 前提

### ポジショニング（`config/strategy.json` / `docs/social_profiles.md` より）

| 項目 | 内容 |
|---|---|
| アカウント名 | トーサイ ｜ 自然体を愛してくれる夫の作り方 |
| 発信者 | 妻とお互い自然体のまま愛し合える関係を築く既婚男性。コーチとして多数のクライアントの夫婦関係・内側の葛藤を観察 |
| 読者 | 結婚歴3〜15年・30代後半〜40代中心の既婚女性。共働き等で経済的に自立している／していた |
| 読者の到達点（ToBe） | 自然体（本音・弱さ・わがまま）のままで夫から愛され、夫の反応に一喜一憂せず、周りに依存せずしなやかに生きている |
| 差別化軸 | 『浮気や離婚は許さない』『自然体でいるために女性の行動変容を促す』 |
| 両輪 | 自分づくり（輪B: `structure` / `permission`）＋ 夫翻訳（輪A: `opinion` / `personal`） |

### ピン留め投稿の役割

- プロフィール訪問者をフォロワーへ転換する
- ターゲット（結婚10年前後の既婚女性）に自己選別させる
- 「この人は何者か」「フォローすると何が届くか」を数秒で伝える

**なぜ今これが最優先か**: フォロワー103名・うちコア層（女性35-54）は23名（2026-08-13 実測。詳細は `CLAUDE.md` の「フォロワー構成の実測」）。この規模では新規リーチを増やすより、**プロフィール訪問→フォローの転換率**を上げる方が投資対効果が高い。

### 構成

2026-08-12 に導入した**投稿の設計骨格**（`scripts/generate_post_ideas.py` の【投稿の設計骨格】）をそのまま使う。

- **第1層 `ideal_state`**: 読者がぼんやり「そうなれたら」と思っているが言語化できていない状態
- **第2層 `method_name`**: そこへ到達する手段の名前（名前だけ出し、中身は補足リプライへ）

ルート＝骨格の2層＋発信者は何者か＋読者の名指し／補足リプライ1＝フォローで届くものと、フォロー誘導。

## 2. 案

### 案A（推奨）: ベネフィット直球型（型F）

| 層 | 内容 |
|---|---|
| `ideal_state` | 夫に本音を言った翌朝も、いつも通りの空気でいられる |
| `method_name` | 自然体を出す順番 |

**本文**

```
夫に本音を言った翌朝も、いつも通りの空気でいられる。

そうなっている妻には、自然体を出す順番があります。

僕は妻とお互い自然体のまま愛し合える関係を続けている既婚男性で、コーチとして多くの夫婦が内側のどこで詰まるかを見てきました。

結婚10年、感謝はされるのに素の自分を愛されている実感が薄い。そんなあなたへ毎日書いています。
```

**補足リプライ1**

```
フォローすると届くもの:

・我慢をほどいても夫の心が離れない、自然体を出す順番
・「察してくれない」の裏で夫が何を考えているかの翻訳
・尽くすほど遠ざかるループから抜けた人が、先にやめたこと

夫の機嫌で自分の一日が決まるのをやめたい人は、フォローも忘れずに。
```

**推奨理由**: 1行目が `ideal_state` の直球で、読者が0.5秒で自分事にできる。実測で伸びた投稿の型（型F）と骨格が一致しており、ピン留めと日々の投稿でトーンが揃う。「結婚10年」で属性を名指しし、25-34帯（ペルソナ外）に誤ってフォローさせない自己選別も効く。

---

### 案B: 状態提示切断型（型I）

| 層 | 内容 |
|---|---|
| `ideal_state` | 夫の機嫌が悪い日でも、自分の一日が崩れない |
| `method_name` | 感情の置き場所の決め方 |

**本文**

```
夫の機嫌が悪い日でも、自分の一日が崩れない妻がいます。

その人たちが先に決めているのは、感情の置き場所です。

僕は妻と自然体のまま愛し合える関係を続けている既婚男性。コーチとして、夫婦がどこで詰まるかを見てきました。

結婚して10年、良い妻でいようとするほど自分が薄くなる。その手前に戻る方法を毎日書いています。
```

**補足リプライ1**

```
このアカウントで扱うこと:

・自然体を出しても夫の心が離れない、感情の置き場所の決め方
・夫が黙る時、男の側で実際に何が起きているかの翻訳
・「わがまま」と「本音」の線引き

離婚や別居が頭をよぎる前に知っておきたい男のアレコレも、既婚男性の立場から書きます。
```

**位置づけ**: `method_name` を伏せて引きを作る型。案Aより一段引きが強い代わりに、読者が得るものの輪郭は薄い。プロフィール文の節3（男のアレコレ）を補足リプライで回収できるのが利点。

---

### 案C: ストーリー切断型（型B・自己開示軸）

| 層 | 内容 |
|---|---|
| `ideal_state` | 良い妻でいようとするほど遠くなった素の自分に戻れる |
| `method_name` | 自然体を出す順番 |

**本文**

```
相手を大切にしようとするほど、自分が苦しくなっていた時期が僕にもあります。

抜けられたのは、自然体を出す順番を変えてからでした。

今は妻とお互い自然体のまま愛し合える関係を続けています。コーチとして、同じ場所で詰まっている夫婦も多く見てきました。

結婚10年前後、良い妻でいるほど素の自分が遠くなる。その戻り方を毎日書いています。
```

**補足リプライ1**

```
フォローすると届くもの:

・自然体を出す順番と、その前にやめること
・夫が本音を返しやすくなる時、男の側で起きていること
・尽くす側に回り続けた人が抜けるまでの過程

素の自分のままで夫に愛されたい人は、フォローも忘れずに。
```

**位置づけ**: 発信者への信頼を先に作る型。共感は取れるが、1行目が発信者主語なので読者の自分事化は案A・案Bより一段遅い。フォロワーが増えて「誰が言っているか」が問われる局面で差し替える候補。

## 3. 執筆時に守ったルール

`scripts/generate_post.py:build_prompt` の共通ルールのうち、3案すべてに効かせたもの:

- 一人称は「僕」、読者＝既婚女性の感情は「あなた」で描く
- 否定型の入り（「〇〇な人は△△だと思ってる。違う。」）を使わない
- 抽象概念を対比させた標語（「テクニックじゃなくマインド」等）で締めない
- 読者を優劣・属性で分類する対比（『良い妻 vs ダメな妻』等）を使わない。状態の片側提示（案B）は可
- 研究・統計の引用、著者名・年・媒体を入れない
- 「思考・行動のクセ」を無修飾で使わない（使う場合は『あなたの／自分の』を冠する。3案とも未使用）
- 「——」（emダッシュ／二倍ダッシュ）を使わない
- 子育ての具体エピソードを発信者の一次経験として書かない（`docs/author_profile.md`：発信者に子どもはいない）

## 4. 運用メモ

- **実アカウントの現ピン留め内容は未確認**。差し替え前に、現在何がピン留めされているかを目視すること。本ファイルの旧版は2世代前のコンセプト（ハイパフォーマー／エンジニア向け）のままだったため、実アカウント側も同世代の投稿が残っている可能性がある
- **公式LINE導線は入れていない**。`config/strategy.json` の `funnel.sns_role` では SNS の最大KPIが公式LINE登録だが、LINE は新規立ち上げ段階（`docs/funnel_design.md`）。稼働後に**補足リプライ2**として追加し、ルート・補足リプライ1には手を入れない想定
- 案を差し替えたら、日々の投稿のフック型が偏っていないか（`generate_post_ideas.py` のフック型カタログ）と合わせて見る。ピン留めと当日投稿が同じ型に寄ると、プロフィール訪問時の情報量が落ちる
