# note 単発2本モデル 設計

最終更新: 2026-08-13

> 無料note 1本・有料note 1本を単発で作り、そこにスキと購入を集中させる運用の設計書。
>
> **本ファイルは実行時に読まれない**（プロンプト生成に利用されない）参照ドキュメント。本文執筆時のルールの正本は `config/note_writing_guide.json`、ポジショニング・ペルソナは `config/strategy.json`。

---

## 1. 背景と狙い

フォロワー103名・コア層（女性35-54）23名という規模では、毎日別記事を出すとスキが1本あたり数件に分散し、どの記事も「人気に見えない」状態になる。**2本に集中させて社会的証明を作る**のが狙い（2026-08-13 運用者判断）。

### 役割は2本で違う

| | 役割 | KPI | 理由 |
|---|---|---|---|
| 無料note | **証明装置** | スキ数 | note で公開表示されるのはスキ数。ここが可視の社会的証明になる |
| 有料note | **収益装置**／ミドルエンドの実体 | 購入数・読後の感想 | **note は購入数を公開表示しない**ため、購入は証明にならない |

「購入を集中させて人気を証明する」は購入側では成立しない。1本に絞る意味は労力削減と実績の実体化にある。

### 単発である前提

日次生成（`generate_note.py` / `note_generate.yml`）は**再開しない**。本文は運用者または Claude が単発で書く。note誘導Threads配信（`post_note_promo.py` / `note_promo.yml`）も**再開しない**。

## 2. テーマ軸

**入口＝「浮気されない妻の特徴」／着地＝「本音を言えなくなってきたこと」の2段構え**（2026-08-13 確定。同日中に入口を変更）

- **入口（無料note のテーマ・タイトル）**: 「浮気されない妻の特徴」。Threads の実測（いいね増→閲覧数増→フォローのきっかけ、という動線を作った投稿の傾向）から、ペルソナの最大の不安が「こんな自分だと浮気されないか心配」だと確認されたため（2026-08-13 運用者観察）。`persona.pain_points` #4 と `tobe_barrier` の「本音を出せば浮気や離婚を招く怖さ」に対応する
- **着地（有料note・手段の語彙）**: 「本音」。`positioning.midend_product.title`「夫に本音が言えなくなってきた時に読みたい愛されガイド」と直結しており、有料note がそのままミドルエンド商品の実体になる。**入口を浮気に変えても着地は変えない**（商品名の変更は商品設計の判断になるため。変えたい場合は `strategy.json:midend_product` とセットで運用者が決める）
- **入口と着地の接続は無料note の中で行う**: 「浮気されない妻の特徴の正体は、夫との間で本音が行き来していること」という逆説が記事の芯。読者は `tobe_barrier` の通り「本音を言うと浮気を招く」と信じているので、この構図の反転自体が記事の最大の発見になる

### 貫く理想状態（設計骨格 第1層）

同じ骨格の**恐れ側と獲得側**を対応させて使い分ける:

| 形 | 言語化 | 使う場所 |
|---|---|---|
| 恐れの解消形 | **夫の浮気が頭をよぎらない毎日でいられる** | 無料note の入口・Threads の浮気系フック |
| 獲得形 | **夫に本音を言った翌朝も、いつも通りの空気でいられる** | ピン留め案A・有料note・Threads の本音系フック |

二つは別の願いではなく、`tobe_barrier` が定義する同一構造（本音を出す怖さ＝浮気への恐れ）の裏表。無料note が記事内でこの二つを接続する。ピン留め投稿（`docs/pinned_post_proposals.md` 案A）は獲得形のまま**変更しない**。

## 3. 無料note

| 項目 | 内容 |
|---|---|
| タイトル | **結婚10年、「浮気されない妻の特徴」を検索したことがある人が最初につまずく場所** |
| タイトル型 | ターゲット明示型（`title_rules.patterns`）＋検索語「浮気されない妻の特徴」をそのまま含める（note 内検索・外部検索の両取り）。ベネフィット直球型は無料note では原則NG |
| ゴール | スキを集める／読者に「自分は落とし穴に入っている」と自覚させる |
| KPI | スキ数。次点で有料note への遷移 |
| 分量 | 3,000〜5,000字 |
| How | 書かない。手段は「本音を置く順番」と命名して提示するだけで、中身は開かない |

### 構成

`config/note_writing_guide.json` の `free_mode_principles.structure_template_override` に反映済み。

| # | セクション | 中身 | 分量比 |
|---|---|---|---|
| 1 | 理想状態の詳細描写 | 恐れの解消形「浮気が頭をよぎらない毎日」を映像化。場面はペルソナの苦痛2点（深夜の確認・検索衝動＝pain #4／本音を飲み込む＝pain #2）に限定 | 2割 |
| 2 | **落とし穴3〜5個** | 読者が自己流で浮気を防ごうとして、すでにハマっている場所。各項目に Why ＋ 夫側の翻訳。**回避策は書かない** | 4割 |
| 3 | 特徴の正体＋手段の名前 | 「浮気されない妻の特徴＝本音が行き来していること」の逆説で本音軸へ接続し、「本音を置く順番」を記事内で命名して提示。中身は開かない | 2割 |
| 4 | ブリッジ・CTA | 落とし穴1つだけ回避策を書き切る（試食）→ 残りは有料へ | 1.5割 |

### 落とし穴の定義（重要）

**「手段を実行した人の失敗」ではなく「読者が自己流で浮気を防ごうとして、すでにハマっている場所」**。手段より前に置く構成なので、手段を知っている前提の落とし穴は成立しない。

現行の4つ: 不安な日ほど急に優しくする／確かめてから安心しようとする／手のかからない妻へ自分を薄めていく／「浮気されない妻の特徴」を外へ探しに行く。4つの共通点（夫の心の中を先回りで管理する＝本音を隠す方向に働く）が、特徴の正体への接続点になる。

### 読者心理の動線

```
これが欲しかった          （1. 理想状態）
  ↓
自分もこれをやっている      （2. 落とし穴）
  ↓
ではどうすれば
  ↓
名前のついた手段があるらしい  （3. 手段の名前）
  ↓
中身が知りたい            （4. ブリッジ）
  ↓
有料note
```

この順序が設計の核心。手段を落とし穴より前に置くと「読んで満足」で閉じられる。

## 4. 有料note

| 項目 | 内容 |
|---|---|
| タイトル | 夫に本音が言えなくなってきた時に読みたい愛されガイド（＝ミドルエンド商品名そのもの） |
| 価格 | **¥980**（`midend_product` のレンジ ¥500〜4,980 内） |
| ゴール | 購入／読了後の「実行できた」感想を得る（次の証明素材になる） |
| 分量 | 8,000〜15,000字 |
| How | ここが核心。全部書く |

### 構成

1. 無料note の落とし穴を要約で回収（無料を読んでいない人にも単体で成立させる）
2. 各落とし穴の回避手順（How の核心）
3. **夫のタイプ別分岐**（黙る夫／反論する夫／話をそらす夫）← 有料の最大価値。無料では絶対に出さない
4. 実行順序（Threads の `method_caveat`「効かせる条件」を体系として束ねる）
5. うまくいかない時の立て直し

**素材の転用**: 旧テーマ（本音軸）時代の無料note 初稿が持っていた落とし穴4つ（本音の量を一度に増やす／言った後に反応を確認しに行く／本音と不満を同じ袋に入れる／夫が黙った時に説明を足す）は、**そのまま有料ガイドの「置く順番」章の素材になる**。本音を出し始めた人がつまずく場所＝手段実行時の失敗、という位置づけで、無料側（手段より前の失敗）と役割が分かれる。旧稿は git 履歴（`output/notes/free_note_honne.md`、コミット `2a0d61b` 時点）から参照できる。

### 価格の根拠

¥500 は「安いから買う」層が混じってスキ・感想が付きにくい。¥4,980 はフォロワー103名・実績ゼロの段階では検証にならない（買わない理由が価格か中身か判別できない）。¥980 は1本きちんと読む動機が立ち、初回購入のハードルも低い。

## 5. 無料 → 有料のブリッジ

`free_mode_principles.midend_handoff`（低圧力・1〜2文）に準拠し、3箇所に置く。

1. **本文中盤**: 落とし穴のうち**1つだけ回避策を書き切る**。有料の質を体験させる試食。これがないと「落とし穴を並べて売りつけた」印象になる
2. **締め**: 「残りの落とし穴の回避と、夫のタイプ別の分岐はガイドで章立てして扱っています」程度の温度
3. **記事末**: 有料note へのリンク

---

## 6. 運用順序

**Threads の先行投稿は公開の前提にしない**（2026-08-13 運用者判断で撤廃。記事は Threads への参照なしで単体で成立する形にしてあり、冒頭の引用ブロック装置も撤去済み）。同テーマの Threads 投稿は、公開後にプロフィール・固定投稿から note へ流す**任意の導線**として扱う。

1. 無料note 公開
2. スキが積み上がる期間を置く（証明装置の稼働期間）。並行して、同テーマの Threads 投稿で導線を増やすのは任意
3. 有料note 公開（無料の**2〜4週間後**が妥当）
4. 無料note に有料へのリンクを追記

## 7. この設計に伴う `note_writing_guide.json` の変更（2026-08-13）

| 分類 | 変更 |
|---|---|
| 削除 | `pattern_distribution`（週次配分＋`free_mode_weekly_caps`）／ `combination_patterns`（5パターン選択）／ `paid_mode_overrides`（combination_patterns への上書きのため連鎖削除）／ `high_performance_patterns.*.recommended_frequency`（週2〜3本）／ `paid_note_selling_elements` の「心理学・脳科学の根拠」要素 |
| 削除理由 | いずれも**連載前提**の仕組みで単発2本では適用不能。加えて `pattern_distribution` / `combination_patterns` は「`generate_note.py` の選択ロジックで」と書かれていたが、そのロジックは本文生成廃止時に既に消えており、記述が実装と乖離していた |
| 置き換え | `free_mode_principles.structure_template_override`（本ファイル §3 の4セクション構成へ） |
| 緩和 | `free_mode_principles.anti_patterns` の Before/After 禁止を「行動レベルの変化は禁止のまま、到達したい状態そのものの描写は対象外」に限定 |
| 更新 | 旧ミドルエンド名「理想の相手の見つけ方ガイド」／旧バックエンド名「マインド構築講座」／旧ペルソナ例「30代独身ITエンジニア」等を現行コンセプトへ |

`how_restriction`（無料note に How を書かない）は**維持**。無料note では手段を命名して提示するに留め、中身の How は有料note へ回す。

追加の変更（2026-08-13・運用者指示）:
- `japanese_language_quality_rules` に第5の契約「**展開契約（圧縮した決め文句の禁止）**」を追加。助詞連結の名詞句や比喩への圧縮＋「〜だけです」の切り詰めを禁じ、主体・経緯・動詞まで開いて事実を書く（bad「変わったのは、夜のスマホとの距離だけです」→ good「大きな変化は、心配になってスマホを手に取る回数が格段に減ったことです」）
- `threads_to_note_handoff` を「参照元の Threads 投稿がある場合のみ」の条件付きに変更（Threads 公開前提の撤廃に伴う）
- `structure_template_override` の理想状態セクションに「場面はペルソナが最も苦しんでいるポイント2つに絞る」制限を追加
